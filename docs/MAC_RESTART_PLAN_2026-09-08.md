# PocketPal 개발 재시작 계획 · 2026-09-08

이번 목표는 **MacBook Air M1에서 직접 실행·시험할 수 있는 P1 기준판을 만들고, 통과 결과를 다음 단계의 기준으로 남기는 것**이다. 최종 목표는 두 자녀용 완성 시제품 2대다. 판매·양산은 실제 사용성 검증 뒤 검토한다.

## 2. 현재 상태를 다시 정리한 이유

확인한 저장소: [MightyMax0614/PocketPal](https://github.com/MightyMax0614/PocketPal).
기준 커밋: `eebe2b06cd0211381d7187dc5d9c47e1d70d8317`.

- README는 P1.4를 설명하지만 시작 페이지는 P1.8 Godot Web을 가리켰다. P1.4 웹, P1.5/1.7 Rive, P1.6 Soul Lab, P1.8 Godot 시험 코드가 병존했다.
- 기존 웹 구현의 문서와 사용자가 실제 평가한 캐릭터 품질은 구분해야 한다. 문서의 ‘고품질/승인’ 표현만으로 외형이 최종 승인됐다고 간주하지 않는다.
- 기본 반응과 ‘실제 생성형 AI 대화’, 그림 얹기와 ‘실제 3D 변환’의 완료 상태를 분리한다.
- 기존 키보드 처리에는 입력창에서도 스페이스·화살표를 메뉴 조작으로 가로채는 문제가 있었다. 해당 코드에 입력창·IME·단축키 보호를 추가했다.
- 기존 소스는 보존하고 `prototype/mac-lab/`과 `Start_PocketPal.command`를 이번 시험의 시작점으로 삼았다. 기존 저장소의 가족 데이터나 NAS 설정은 수정하지 않았다.

## 4. 단계별 실행 계획

기간은 **1회 60~90분 작업 기준의 계획 추정**이다. 달력에 맞춰 실패를 덮고 넘어가지 않는다.

| 순서 | 작업 | 산출물 | 통과 기준 |
|---|---|---|---|
| M0 · 이번 패키지 | 로컬 실행판·진단·백업 기반 정리 | 실행 ZIP, 재시작 계획, 시험 기록 양식 | 자동 검사와 가능한 화면 시험 결과를 명시 |
| M1 · 1~2회 | 사용자 맥북 첫 20분 시험 + 재시작/오프라인 시험 | 실제 macOS·브라우저·오류가 적힌 시험 결과 JSON | 빈 화면 없음, 한글 입력 정상, 두 아이 기억 혼합 0건, 선물/기억 재실행 유지 |
| M2 · 2~3회 | 캐릭터 최종 방향 고정. 기존 원본 자산/라이선스/애니메이션 확인 | 실제 자산, 부착점 표, 동일 캐릭터의 대기·인사·기쁨·수면·쓰다듬기 비교 | 사용자가 외형·동작을 직접 수용. 캐릭터 흔들림·파트 분리·화면 깨짐 없음 |
| M3 · 3~5회 | 로컬 AI 실제 대화, 한국어 TTS/STT, 기억 확인/수정/삭제 흐름 | 10개 시험 대화, 응답 속도 기록, 기억 정책 | 답변 10개 중 이름·명시 기억 확인 9개 이상 성공. 응답시간 중앙값 목표 5초 이내/90% 10초 이내는 측정 목표이며 보장 아님 |
| M4 · 3~5회 | 액세서리 한 종류의 실제 3D 선물 경로 완성 | 배지 또는 모자의 GLB 3개, 앵커·축·단위 명세, 착용 미리보기 | 3개 그림이 모두 GLB로 열림, 같은 부착점에 붙음, 재실행 후 유지. 실패한 결과를 성공으로 표시하지 않음 |
| M5 · 2~4회 | NAS 기억·처리 연결, 스마트폰 전·후면 카메라·AR 검증 | 재연결 시험, 송신 데이터 표시, 가족별 격리 결과 | NAS 끊어져도 핵심 기억·캐릭터 유지, 연결 후 중복/덮어쓰기 없음. 실제 스마트폰 카메라 두 개 확인 |
| P2 · M1~M4와 병행 | 104×62×12.0mm 실물 크기 모형. 화면·휠·카메라 영역 대조 | 종이/보드 모형과 손에 쥔 사진, 실제 치수 표 | 두 아이 그립·클릭휠 닿음·화면 가림 확인. 100% 출력 치수 실측 |
| EVT0 진입 | 기존 기기로 카메라·소리·메모리·휠 신호 통합 | 책상 위 기능 연결체 | M1~M5 핵심 오류 해소, P2 그립 통과. 이때 필요한 최소 개발 부품만 국내 재고 조사 |

P2 치수 검토상 2.8인치 3:4 화면의 활성 영역은 계산으로 약 **42.67×56.90mm**다. 세로 56.90mm와 40mm 휠만 더해도 약 96.90mm여서 104mm 외형 안에 세로 여유가 약 7.10mm다. 여기에 디스플레이 모듈 외곽·FPC·카메라·여유 공간을 넣어야 한다. 이는 기존 사양을 줄이는 결정이 아니라 **실제 부품 데이터시트로 가장 먼저 검증해야 할 배치 제약**이다. 이번 화면의 확대 모형은 제조용 CAD가 아니다.

## 5. 먼저 맥북에서 할 일

1. ZIP을 다운로드하고 압축을 푼다. 내부 `START_HERE.html`을 열면 설치·실행 안내가 나온다.
2. `Start_PocketPal.command` 실행. 터미널 창과 `http://127.0.0.1:8765` 화면이 열린다. 터미널은 사용 중 유지한다.
3. 첫째를 선택하고 설정에서 시험용 이름을 저장한다. 기억 탭에 “티라노사우루스를 좋아해”를 저장한다.
4. 대화에서 “내가 좋아하는 걸 기억해?”라고 묻는다. 한글·스페이스·화살표 편집을 함께 확인한다.
5. 선물 탭에 작은 PNG/JPG 그림을 올린다. 배지/머리/손 중 위치를 골라 선물하고 인사·점프를 누른다.
6. 둘째로 전환해 첫째의 기록이 보이지 않는지 확인한다. 둘째도 별도 이름/기억을 저장한다.
7. 첫째로 돌아와 저장 상태 확인 → 터미널 Control+C → 재실행 → 같은 상태가 남는지 확인한다.
8. Wi-Fi를 끄고 기본 반응·기억 조회·그림 선물을 다시 확인한다. 음성은 사전 설치된 로컬 한국어 음성이 필요하다.
9. 설정에서 백업을 받고 **시험 데이터**를 삭제·복원해 본다. 복원은 두 프로필 전체를 교체한다.
10. 시험 순서 탭의 확인 항목을 표시하고 결과 JSON을 다운로드한다. 이후 수정은 이 결과를 기준으로 한다.

맥북 실기 시험은 사용자 기기에 대한 원격 제어가 연결되어 있지 않으므로 사용자가 실행해야 한다. 제공 환경의 테스트 성공을 사용자 맥북 성공으로 표기하지 않는다.

## 6. 실제 AI 대화 연결

기본 반응 확인이 끝난 뒤 진행한다.

- Ollama의 현재 macOS 요구사항은 Sonoma 14 이상이다. Apple M 시리즈는 CPU/GPU를 지원한다. [공식 요구사항](https://docs.ollama.com/macos)
- [Ollama macOS 다운로드](https://ollama.com/download/mac)에서 설치하고 실행한다.
- 터미널에서 `ollama pull qwen3:1.7b`를 실행한다. 이 모델은 M1 기본형에서 시작할 **잠정 후보**이며 한국어 품질·속도를 보장하지 않는다. [모델 페이지](https://ollama.com/library/qwen3:1.7b)
- 설치 후 PocketPal 설정 → AI 연결 확인 → 모델 선택 → 대화 방식 ‘로컬 AI’를 선택한다.
- 앱은 로컬 주소 `127.0.0.1:11434`의 `/api/chat`를 사용한다. 설치된 로컬 모델만 허용하고 `:cloud`나 `remote_host` 모델은 제외한다. [공식 API](https://docs.ollama.com/api/chat)
- 모델 다운로드에는 인터넷과 저장 공간이 필요하다. 모델 크기에 더해 실행 메모리가 필요하므로 활동 모니터에서 메모리 압박을 확인한다. 동시에 실행 중인 큰 앱은 시험 시 줄인다.
- 처음 모델을 읽는 시간과 후속 응답 시간을 나눠 기록한다. 한국어 성능이 부족하면 측정 결과를 보고 모델을 바꾼다.
- ChatGPT Plus/Google AI Pro 등 기존 구독을 이 앱의 API 권한으로 자동 사용하지 않는다.

## 7. 다음 개발 구조

이번 P1은 화면과 상태 저장을 로컬에서 검증한다. 이후에도 코드가 일회용이 되지 않도록 프로필·기억·선물 데이터를 JSON으로 내보낼 수 있다.

| 위치 | 역할 | 다음 연결 원칙 |
|---|---|---|
| Mac/휴대 기기 | 캐릭터 상태·입력·핵심 기억·알람·로컬 대화 | 연결 단절이 기본 교감을 막지 않도록 한다 |
| UGREEN NAS | 장기 기억·사진·음성/이미지 처리·3D 작업 | 가족/아이 ID를 모든 작업에 포함하고 재시도/중복 방지 구현 |
| Hermes | 복잡한 대화/도구 호출이 필요할 때의 조정 계층 | 현재 설치를 활용하되 인증·API 규격을 실제 확인한 뒤 연결 |
| n8n | 백업·그림 처리 작업의 예약/연결 | 오프라인 실시간 캐릭터 동작의 필수 경로로 만들지 않음 |
| 클라우드 | 고급 이미지 이해·복잡한 대화·필요한 3D 생성 | 보호자에게 전송 항목과 비용을 먼저 보이고 선택적으로 사용 |

3D 선물 작업은 `job_id / child_id / input_image / category / status / error / result_glb / anchor / scale / rotation / license`를 기록한다. 초기 한 종류의 성공률을 먼저 확보하고 의상으로 확장한다. 대기/실패/사용자 보정 필요 상태를 실제 결과와 일치시킨다.

## 8. 다음 단계를 시작하는 기준

- **우선순위 1:** 맥북에서 빈 화면 없이 실행하고 기억·선물·프로필 분리가 유지되는가?
- **우선순위 2:** 사용자가 실제로 만족하는 캐릭터 원본과 동작이 확보됐는가?
- **우선순위 3:** 실제 AI 응답과 로컬 음성이 아이와 교감하기에 충분한가?
- **우선순위 4:** 실제 GLB 선물 1종이 처음부터 끝까지 완주하는가?
- 이 네 기준을 통과하기 전 하드웨어 선택과 새 기능 추가로 방향을 분산하지 않는다. 카메라 두 개·평면 클릭휠·얇은 외형은 끝까지 검증 대상에 유지한다.

## 9. 시험 환경·한계

자동 테스트는 임시 데이터베이스로 실행하며 사용자의 실제 대화·사진·NAS를 사용하지 않는다. 테스트 내 Ollama 응답은 모의 서버 함수로 대체했다. 실제 LLM 한국어 품질/지연, Safari, macOS 실행 권한 처리, 카메라와 로컬 음성은 맥북 실기 시험에 남긴다. 상세 실행 결과는 패키지의 `docs/VALIDATION_2026-09-08.md`를 참고한다.

기술 기준을 확인한 공식 문서: [Python macOS 설치](https://www.python.org/downloads/macos/), [Ollama macOS](https://docs.ollama.com/macos), [Ollama Chat API](https://docs.ollama.com/api/chat), [Qwen3 1.7B](https://ollama.com/library/qwen3:1.7b).
